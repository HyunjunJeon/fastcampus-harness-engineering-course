# Session 2-1. Explore -> Plan -> Implement -> Commit 흐름 만들기

## 목표

AI에게 바로 수정시키지 않고, 탐색, 계획, 구현, 저장 단계를 분리하는 기본 루틴을 만든다. 수강생은 작은 작업도 변경 계약과 검증 기준을 먼저 세운 뒤 실행할 수 있어야 한다.

Agent1 >> 탐색 -> 계획(의미가 없어짐) -> 구현

[격리]                                          [합치기]

Agent2 >>     수정: 

## 준비물

- 실습용 Git 저장소
- 변경할 작은 이슈 하나
- `git status`, `git diff`, `git branch` 사용 가능 환경

## 진행 순서

1. 나쁜 시작과 좋은 시작을 비교한다.
   - 나쁜 요청: "이 프로젝트 고쳐줘"
   - 좋은 요청: "먼저 구조를 읽고, 수정할 파일과 검증 방법을 계획해줘"

2. Explore 단계를 만든다.
   - 관련 파일 찾기
   - 현재 동작 이해
   - 변경 위험도 파악
   - 수정 후보 범위 좁히기

3. Plan 단계를 만든다.
   - 바꿀 파일
   - 바꾸지 않을 파일
   - 테스트 또는 확인 방법
   - 실패 시 되돌릴 방법

4. Implement 단계를 실행한다.
   - 계획과 다른 파일을 건드리면 멈춘다.
   - 한 번에 한 단계씩 작은 diff를 만든다.
   - AI의 설명보다 실제 diff를 우선한다.

5. Commit 단계는 사람이 승인한다.
   - 커밋은 AI가 만든 결과가 아니라 사람이 검토한 변경을 저장하는 행위다.
   - push 여부는 별도 결정으로 남긴다.

## 데모/실습

작은 README 수정 또는 단일 버그 수정으로 4단계 프롬프트를 작성한다.

```text
Explore:
이 작업과 관련된 파일을 먼저 찾아줘. 아직 수정하지 마.

Plan:
수정할 파일, 수정하지 않을 파일, 검증 명령, 위험 요소를 계획으로 정리해줘.

Implement:
계획에 포함된 파일만 최소 범위로 수정해줘.

Commit 준비:
git diff 기준으로 변경 요약, 검증 결과, 남은 리스크를 정리해줘.
```


## 완료 기준

수강생이 모든 AI 작업을 최소한 `읽기 -> 계획 -> 수정 -> 검증 -> 저장` 단계로 나눠 요청할 수 있어야 한다.
