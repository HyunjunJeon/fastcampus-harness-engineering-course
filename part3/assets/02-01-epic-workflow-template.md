# 02-01 EPIC 워크플로 템플릿

[../plan.md](../plan.md) 02-01 진행 흐름의 4단계(짧은 실습)에서 사용. EPIC 4단계의 입출력 정의 + 1쪽 체크리스트 양식.

## EPIC 4단계 입출력 정의

| 단계 | 입력 | 사람이 끼어드는 위치 | AI 산출물 | 사람 결정 |
| --- | --- | --- | --- | --- |
| **Explore** | 작업 요청 한 줄 | (없음 — 읽기만) | 영향 받는 파일·함수 목록 + 모르는 부분 표시 | 목록 검토 |
| **Plan** | Explore 결과 | "이 계획이 맞나?" | 변경 없는 계획서 (단계·예상 diff 위치) | 계획 승인 |
| **Implement** | 승인된 계획서 | 부분 diff마다 검토 | 단계별 작은 diff (10~50줄) | diff 승인 |
| **Commit** | 통과한 diff | 커밋 메시지 검토 | 메시지 후보 + 검증 명령 | push 결정 |

## 1쪽 체크리스트 양식

수강생이 본인 `docs/epic-workflow.md`에 채울 양식:

```markdown
# 내 EPIC 워크플로

## Explore 단계
- [ ] AI가 이 작업으로 *영향 받는 파일* 목록을 만들었나
- [ ] AI가 *모르는 부분*을 "확인 필요"로 표시했나
- [ ] 내가 이 목록을 한 번 읽었나

## Plan 단계
- [ ] AI가 변경 *없는* 계획서를 만들었나 (코드 수정 X)
- [ ] 계획서의 단계 수가 5개 이하인가 (많으면 다시 분해)
- [ ] 내가 계획을 한 번 읽고 "예/아니오" 답했나

## Implement 단계
- [ ] AI가 한 번에 1단계씩만 진행하는가
- [ ] 단계별 diff가 50줄 이하인가
- [ ] 내가 각 diff를 한 번 읽고 승인했나

## Commit 단계
- [ ] AI가 커밋 메시지의 *왜*를 설명했나
- [ ] 검증 명령(test/lint)이 통과했나
- [ ] push는 *내가* 결정했나
```

## 단계를 건너뛰고 싶은 유혹 (강사가 짚어줄 지점)

| 유혹 | 어디서 생기나 | 어떻게 막나 |
| --- | --- | --- |
| Plan을 건너뛰고 바로 Implement | "답이 뻔해 보이는" 작은 작업 | 첫 시도 *전부*에 Plan 단계를 강제, 익숙해진 뒤 선택적 생략 |
| Explore를 건너뛰고 바로 Plan | "이 코드 안다" 익숙한 영역 | Explore 산출물 1줄 길이 메모만이라도 강제 |
| Commit 검증 건너뛰기 | 시간 부족 | 검증을 04-02 훅으로 *도구가 강제* |

## 강사가 챙길 자산

- 단계 건너뛰기 유혹 지점 1~2개 본인 경험 메모
