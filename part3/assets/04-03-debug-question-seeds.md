# 04-03 디버깅 질문 카탈로그 시드

[../plan.md](../plan.md) 04-03 진행 흐름의 4단계(짧은 실습)에서 사용. 4 카테고리 × 시드 질문 + 일부러 실패하는 케이스 예시.

## 4 카테고리 × 시드 질문 8개

수강생이 본인 `docs/debug-question-catalog.md`에 *적어도 5개*를 가져갈 출발점.

### A. 증상 분리

1. *원하는 동작*을 한 문장으로 적어줘. 예: "음수 두 개를 더하면 음수가 나와야 한다."
2. *실제로 일어난 동작*을 한 문장으로 적어줘. 코드 실행 결과를 *그대로* 인용.

### B. 가설 끌어내기

3. 위 두 동작의 *차이*를 설명할 수 있는 가설을 3개 제시해줘. 가장 가능성 높은 것부터.
4. 각 가설마다 *어디가* 잘못됐는지 추정 위치(파일·함수·줄)를 짚어줘.

### C. 실험 설계

5. 가설 1을 검증할 *가장 작은 실험*을 알려줘. 코드 수정 없이 *읽거나 출력만*으로 가능한 실험이면 더 좋음.
6. 실험의 *예상 결과*를 가설이 맞을 때와 틀릴 때 각각 적어줘.

### D. 결과 기록

7. 실험 결과를 한 줄로 적어줘 — 가설이 *지지*되었나, *반증*되었나?
8. 다음 실험은 무엇이고, 그 이유는?

## 일부러 실패하는 작은 케이스

다음 코드를 수강생 환경에서 돌려 실패를 만들고 위 카탈로그로 디버깅 시연.

```python
# src/calculator.py
def add(a, b):
    return abs(a) + abs(b)  # 일부러 잘못된 구현: 항상 양수 반환
```

```python
# tests/test_calculator.py
from src.calculator import add


def test_add_handles_negatives():
    assert add(-2, -3) == -5
```

실행:

```bash
pytest tests/test_calculator.py -v
```

결과: **FAIL** — `assert 5 == -5` 같은 에러.

### 시연 흐름

수강생에게 실패 로그를 보여주고 위 4 카테고리를 순서대로 묻는다.

1. **A-1 원하는 동작**: "음수 두 개를 더하면 음수가 나와야 한다."
2. **A-2 실제 동작**: "음수 두 개를 더했더니 5가 나왔다."
3. **B-3 가설 3개**: (a) `add`가 `abs`를 쓴다, (b) 테스트의 기댓값이 잘못됐다, (c) import가 잘못됐다.
4. **C-5 가장 작은 실험**: 가설 (a) — `src/calculator.py`를 *읽기만*으로 검증 가능. 코드 수정 없이.
5. **D-7 결과 기록**: 가설 (a) 지지됨 → 다음 단계는 *수정*.

이 흐름이 *답을 모르는* 다른 버그에도 그대로 적용된다는 점을 강조한다.

## "고쳐줘"부터 시키지 말 것 — 비교 시연

같은 실패에 대해 두 가지 프롬프트를 비교한다.

| 나쁜 프롬프트 | 좋은 프롬프트 |
| --- | --- |
| "테스트 실패해. 고쳐줘." | "이 에러를 바로 고치려고 하지 마. 먼저 A·B·C·D 카테고리로 분리해줘." |

나쁜 프롬프트는 AI가 *추측하는 수정*을 내놓을 가능성이 크다. 좋은 프롬프트는 *가설·실험을 강제*해 사람이 검토 가능한 형태로 만든다.
