# Session 1-3. Codex 승인 모드와 작업 공간 접근 범위 이해하기

## 목표

Codex의 승인 정책과 샌드박스 설정을 작업 공간 접근 범위 관점에서 이해한다. 수강생은 작업을 시작하기 전에 해당 세션이 어디까지 읽고 쓸 수 있어야 하는지 판단할 수 있어야 한다.

## 준비물

- Codex config reference
- Codex AGENTS.md guide

## 진행 순서

1. Codex 설정의 핵심 축을 설명한다.
   - 승인 정책
   - 샌드박스 모드
   - workspace write 범위
   - 네트워크 접근
   - 프로젝트 신뢰 설정

2. 샌드박스를 실패 반경으로 설명한다.
   - 읽기 전용은 탐색과 계획에 적합하다.
   - workspace write는 일반적인 로컬 수정에 적합하다.
   - full access는 강력하지만 실패했을 때 영향이 커서 별도 판단이 필요하다.

3. 승인 정책을 운영 모드로 설명한다.
   - 대화형 실습에서는 사람이 승인하는 모드가 학습에 좋다.
   - 비대화형 자동화에서는 거부되거나 실패하도록 설계하는 편이 안전할 수 있다.
   - 촬영일 기준으로 실제 옵션명과 deprecated 여부를 공식 문서에서 다시 확인한다.

4. 두 config 예시를 비교한다.
   - `workspace-write + on-request`: 일반 업무, 파일 쓰기 가능, 외부 명령은 승인 요청
   - `read-only + untrusted`: 새 저장소 탐색, 어떤 변경도 일어나지 않음

5. 프로젝트 신뢰와 로컬 설정을 다룬다.
   - 프로젝트별 설정은 편리하지만, 신뢰하지 않는 저장소에서는 위험할 수 있다.
   - AGENTS.md는 행동 지시문이고, 실제 실행 권한은 승인/샌드박스 설정이 정한다.

## 데모/실습

같은 작업을 두 모드로 비교한다. 예시는 "이 파일 한 줄 고쳐줘"처럼 작게 잡는다.

```text
이 작업을 바로 실행하지 말고, Codex에서 필요한 sandbox/approval 범위를 먼저 제안해줘.
각 선택지의 장단점과 실패했을 때 영향을 함께 설명해줘.
```

수강생이 다음 표를 채운다.

```text
작업:
필요한 읽기 범위:
필요한 쓰기 범위:
네트워크 필요 여부:
승인 필요 여부:
추천 Codex 실행 범위:
확인할 공식 문서:
```

## Windows/WSL 주의

- Windows native Codex, WSL2 Codex, Desktop App은 샌드박스와 파일 접근 체감이 다를 수 있다.
- 수강생에게 현재 Codex가 바라보는 프로젝트 루트와 실제 Git 저장소 루트를 먼저 확인하게 한다.

## 산출물

Codex 세션 시작 전 체크리스트:

```text
오늘 맡길 작업:
읽기 범위:
쓰기 범위:
네트워크:
승인 정책:
샌드박스:
금지 파일:
검증 명령:
```

## 완료 기준

수강생이 Codex에게 작업을 맡기기 전에 어떤 파일과 네트워크 접근을 허용할지 직접 선택할 수 있어야 한다.

## 촬영 전 확인

- Codex config 문서에서 sandbox/approval 키 이름을 다시 확인한다.
- 같은 요청이 두 모드에서 어디서 멈추는지 미리 녹화용 메모를 만든다.
