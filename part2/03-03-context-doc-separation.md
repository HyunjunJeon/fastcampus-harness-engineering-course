# Session 3-3. 1개의 대화 세션 컨텍스트를 지키는 컨텍스트-문서 분리 전략

## 목표

대화에 둘 정보와 문서로 뺄 정보를 구분한다. 
긴 대화 하나를 억지로 유지하는 것이 아니라, 필요한 컨텍스트를 알맞은 위치에 배치한다.

## 준비물

- `CLAUDE.md` 또는 `AGENTS.md`
- `context-map.md` 템플릿
- 공식 문서 링크 목록

## 진행 순서

1. 컨텍스트를 4개 층으로 나눈다.
   - 즉시 프롬프트: 지금 한 번만 필요한 요청
   - 세션 핸드오프: 현재 작업을 이어가기 위한 요약
   - 프로젝트 문서: 반복해서 필요한 규칙, 명령, 결정
   - 외부 공식 문서: 제품 기능, API, 최신 사용법

2. 정보를 어디에 둘지 판단한다.
   - 오늘만 필요한 요청: 대화
   - 내일 이어서 해야 할 작업: 핸드오프 노트
   - 매번 지켜야 할 규칙: `CLAUDE.md` 또는 `AGENTS.md`
   - 계속 바뀌는 제품 기능: 공식 문서 링크와 확인 날짜
   - 길고 자주 바뀌는 배경 자료: 별도 문서

3. 긴 프롬프트를 분해한다.
   - 지금 요청
   - 프로젝트 규칙
   - 배경 설명
   - 외부 참고 링크
   - 환경 정보

4. 최종 작업 루프를 만든다.
   - 공식 문서에서 기능 확인
   - 좋은 질문으로 실습 전환
   - 반복 규칙은 문서화
   - 긴 세션은 핸드오프
   - 다음 세션은 문서와 완료 기준으로 시작


## 데모

```text
아래 긴 지시문을 분해해서 어디에 두면 좋은지 분류해줘.
분류 기준은 "이번 대화에만 둘 내용", "AGENTS.md/CLAUDE.md에 둘 규칙", "별도 문서로 뺄 배경", "공식 문서 링크로 남길 내용"이야.
각 항목을 왜 그 위치에 두는지도 설명해줘.
```

## 산출물

`context-map.md`:

```markdown
| 정보 | 위치 | 이유 | 갱신 주기 |
| --- | --- | --- | --- |
| 현재 작업 목표 | 대화/핸드오프 | 자주 바뀜 | 매 세션 |
| 테스트 명령 | AGENTS.md | 반복 규칙 | 변경 시 |
| 공식 문서 링크 | references | 최신성 필요 | 촬영 전 |
```

## 완료 기준

수강생이 긴 프롬프트를 더 길게 만드는 대신, 정보의 성격에 따라 대화, 규칙 문서, 핸드오프 문서, 공식 문서 링크로 나눌 수 있다.
