# Session 3-2. /compact, resume, memory를 언제 어떻게 쓸까

## 목표

`/compact`, `resume`, `memory` 같은 기능을 만능 해결책이 아니라 컨텍스트 관리 보조 도구로 이해한다. 중요한 결정은 기능에 맡기지 않고 파일로 남긴다.

## 진행 순서

1. 기능별 역할을 구분한다.
   - compact: 현재 대화의 핵심을 압축해 이어간다.
   - resume: 이전 대화나 작업 흐름을 다시 불러온다.
   - memory: 반복 참고할 사용자/프로젝트 정보를 저장하거나 읽는다.
   - 문서화: 세션 밖에서도 남아야 할 정보를 파일로 고정한다.

2. 한계를 설명한다.
   - 압축은 손실이 있을 수 있다.
   - resume은 모든 맥락을 완벽히 되살린다는 뜻이 아니다.
   - memory는 항상 현재 작업에 맞는다는 뜻이 아니다.
   - 중요한 결정은 프로젝트 문서에 남긴다.

3. 사용 시나리오를 나눈다.
   - 같은 작업을 조금 더 이어갈 때: compact
   - 어제 하던 작업을 다시 열 때: resume 또는 핸드오프 문서
   - 반복되는 개인 선호나 프로젝트 규칙: memory 또는 규칙 문서
   - 팀 전체가 공유해야 하는 규칙: 저장소 문서

4. 실제 명령 확인 루틴을 보여준다.
   - 공식 문서 확인
   - `/help`, `--help` 확인
   - 로컬 설정 파일 확인
   - 현재 버전에서 없거나 다른 이름이면 촬영일 기준으로 표시

5. 기능 사용 후 검증한다.
   - AI에게 현재 목표와 남은 작업을 요약하게 한다.
   - 핸드오프 노트와 비교한다.
   - 빠진 결정은 사람이 문서에 보강한다.

## 데모

```text
지금까지의 대화를 다음 세션으로 넘길 수 있도록 요약해줘.
반드시 포함할 항목은 목표, 완료된 작업, 남은 작업, 중요한 결정, 검증 명령, 절대 바꾸면 안 되는 파일이야.
불확실한 내용은 확정하지 말고 "확인 필요"로 표시해줘.
```
